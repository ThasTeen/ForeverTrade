## Что должно заработать

1. **Контроль завершенности записи Lua (Аудит §4):** `_wait_for_file_ready()` возвращает `False` при незавершенном файле и прерывает ETL; не принимать резервную копию `.bak` старше последней импортированной генерации.
2. **Изоляция автоопределения реалма (Аудит §5):** Автовыбор реалма не должен навсегда перезаписывать настроенный реалм watcher (`self.realm`).
3. **Хронологический выбор цены (Аудит §7):** При отсутствии полей `m`/`mr` выбирать значение из таблиц `h`/`l` с максимальным числовым timestamp.
4. **Поддержка аргумента `--run-once` (Аудит §16):** В `run_watcher.py` реализовать CLI-флаг `--run-once` с корректным разовым выполнением ETL/дашборда и чистым выходом.
5. **Защита от SQLite OverflowError (Аудит §17):** Валидировать числовые границы SQLite INTEGER (`-9223372036854775808 <= x <= 9223372036854775807`) для `item_id` и цен.
6. **Атомарная дедупликация (Аудит §18):** Использовать `BEGIN IMMEDIATE` в транзакции дедупликации метаданных и снимков для исключения гонки между процессами.

## Критерии приёмки

- [ ] Неполный Lua-файл отбрасывается, старый `.bak` не перетирает свежий снимок
- [ ] Watcher сохраняет исходный настроенный реалм
- [ ] Из исторических таблиц `h`/`l` выбирается самый свежий timestamp
- [ ] `python run_watcher.py --run-once --realm ...` отрабатывает без ошибок `unrecognized arguments`
- [ ] Чрезмерно большие числа отсекаются без падения по `OverflowError`
- [ ] Дедупликация снимков атомарна при параллельных процессах
- [ ] Тесты в `tests/test_etl.py` подтверждают исправления
