# Инженерный план разработки аналитического агента WoW: Forever

Данный документ регламентирует структуру, технологический стек, этапы разработки и контрольные артефакты для создания автономного агента рыночной аналитики.

---

## 1. Архитектура и стек технологий

```
               [ Клиент WoW Forever ]
                         │
      (/reload или Logout сбрасывает данные)
                         ▼
             [ WTF/.../Auctionator.lua ]
                         │
        (Событие FileModified / FileClosed)
                         ▼
        ┌───────────────────────────────────┐
        │        ETL Ingestion Engine       │
        │  • watchdog (Event Listener)      │
        │  • luadata (Безопасный парсер)    │
        │  • Дедупликатор (окно 10 минут)   │
        └─────────────────┬─────────────────┘
                          ▼
        ┌───────────────────────────────────┐
        │      SQLite Time-Series Base      │
        │  • items / recipes / reagents     │
        │  • price_snapshots                │
        └─────────────────┬─────────────────┘
                          ▼
        ┌───────────────────────────────────┐
        │     Arbitrage & Analytics Core    │
        │  • Vendor Arbitrage Engine        │
        │  • Crafting Margin Engine         │
        │  • Z-score Anomaly Detector       │
        └─────────┬───────────────────┬─────┘
                  │                   │
                  ▼                   ▼
        ┌───────────────────┐  ┌─────────────────────┐
        │    LLM Advisor    │  │  Autonomous Portal  │
        │  • Ollama / JSON  │  │  • dashboard.html   │
        │  • Тактический гид│  │  • Plotly.js charts │
        └───────────────────┘  └─────────────────────┘
```

* **Язык разработки:** Python 3.11+
* **База данных:** SQLite 3 (с индексами временных рядов)
* **Парсинг данных:** `luadata` (строгая десериализация без eval)
* **Файловый мониторинг:** `watchdog`
* **Математика и аналитика:** `pandas`, `numpy`
* **Визуализация:** `Plotly.js`, HTML5, CSS Grid (автономный бандл)
* **AI-ассистент:** Локальный инференс через Ollama (`llama3.2:3b` / `qwen2.5:7b`)

## 2. Поэтапный план реализации

### Спринт 1: Архитектура базы данных и нормализация справочников
**Цель:** Создать схему БД SQLite и наполнить статическую базу игровых предметов и рецептов.

* [ ] **Задача 1.1: Развертывание DDL схемы БД**
  * Создать таблицы `items`, `price_snapshots`, `recipes`, `recipe_reagents`.
  * Создать составные индексы `idx_snapshots_item_time` и `idx_snapshots_realm_time`.
* [ ] **Задача 1.2: Сбор базового каталога Classic Era**
  * Сформировать парсер статических предметов WoW Era 1.15 для извлечения `item_id`, `name`, `quality`, `item_class`, `item_subclass`, `vendor_sell_price`, `vendor_buy_price`.
* [ ] **Задача 1.3: Создание слоя изменений Forever (`forever_overrides.json`)**
  * Внести уникальные предметы сервера: контейнеры *Waylaid Crates*, бивачные предметы, ремесленные грамоты.
* [ ] **Задача 1.4: Формирование графа ремесел**
  * Заполнить рецепты и компонентные затраты для: Инженерии (трубки, каркасы, винты), Портняжного дела (сумки, рулоны), Кожевничества (накладки, обработанные шкуры), Алхимии (зелья, трансмутации).
* **Артефакт этапа:** Готовые базы `market.db` и файл переопределений `forever_overrides.json`.

### Спринт 2: Построение службы мониторинга и ETL-пайплайна
**Цель:** Обеспечить фоновый перехват свежих срезов цен при каждом сбросе файла `Auctionator.lua`.

* [ ] **Задача 2.1: Монитор файловой системы (`Watcher Engine`)**
  * Реализовать слушатель на базе `watchdog.observers.Observer`.
  * Перехватывать события завершения записи в файл `WTF/Account/<ACCOUNT>/SavedVariables/Auctionator.lua`.
* [ ] **Задача 2.2: Безопасный синтаксический анализ**
  * Интегрировать библиотеку `luadata` для десериализации таблицы `AUCTIONATOR_PRICE_DATABASE`.
  * Настроить fallback-обработку: при сбое чтения или повреждении файла производить чтение из резервной копии `Auctionator.lua.bak`.
* [ ] **Задача 2.3: Дедупликация и нормализация**
  * Добавить валидацию временной метки: если с момента предыдущего снимка прошло менее 10 минут и данные идентичны — пропускать транзакцию.
  * Извлекать базовый `item_id` из расширенной сигнатуры `itemId:enchantId:gem1:...`.
* [ ] **Задача 2.4: Пакетная вставка (Batch Ingestion)**
  * Реализовать сохранение через `cursor.executemany` в таблицу `price_snapshots`.
* **Артефакт этапа:** Фоновая служба инжеста с логированием в `watcher.log`.

### Спринт 3: Аналитическое ядро и арбитражные расчеты
**Цель:** Разработать вычислительные модули для выявления неэффективностей рынка.

* [ ] **Задача 3.1: Алгоритм вендорного арбитража**
  * Реализовать запрос на поиск лотов с условием $P_{\text{buyout}} < V_{\text{sell}}$ и чистой прибылью $\ge 50$ меди.
  * Сортировать выборку по абсолютной прибыли в меди/серебре.
* [ ] **Задача 3.2: Калькулятор ремесленной маржи**
  * Рассчитывать полную себестоимость компонентов $\sum (C_{\text{in}, i} \times Q_i)$.
  * Учитывать скидку $5\%$ на покупку у вендоров (`Bartering`) и вероятность дополнительного выхода продукции (`Master Chef`).
  * Фильтровать рецепты с комиссией биржи $5\%$ ($\tau = 0.05$) и минимальным $\text{ROI} \ge 25\%$.
* [ ] **Задача 3.3: Модуль статистического снайпинга ($Z$-score)**
  * Настроить расчет скользящего среднего $\mu$ и отклонения $\sigma$ по окну последних 10–20 снимков.
  * Выставлять триггеры $Z \le -1.8$ (*Strong Buy / Панический сброс*) и $Z \ge 1.6$ (*Sell / Локальный пик*).
* **Артефакт этапа:** Модуль `analytics_engine.py`, возвращающий структурированные датафреймы сделок.

### Спринт 4: Визуализация и генерация автономного отчета
**Цель:** Создать легковесный дашборд для наглядной оценки рыночной ситуации.

* [ ] **Задача 4.1: Генератор статического портала (`dashboard.html`)**
  * Сборка автономного HTML-файла без необходимости развертывания веб-сервера.
  * Встраивание библиотеки Plotly.js для отображения динамики цен на сырье и расходники.
* [ ] **Задача 4.2: Интерактивные таблицы сигналов**
  * Добавить отображение блоков «Вендорный арбитраж», «Крафт под Waylaid Crates», «Аномальные сбросы цен».
  * Цветовая индикация денежных сумм (золото, серебро, медь).
* [ ] **Задача 4.3: Система локальных уведомлений**
  * Реализовать отправку нативных системных уведомлений ОС (`win10toast` / `plyer` / терминальный звонок), если найден вендорный арбитраж с прибылью более $1$ золотого.
* **Артефакт этапа:** Модуль `build_standalone_dashboard()` и шаблон `dashboard.html`.

### Спринт 5: Интеграция стратегического AI-ассистента
**Цель:** Автоматически формировать текстовый план действий на игровую сессию на основе рыночных данных.

* [ ] **Задача 5.1: Формирование компактного JSON-контекста**
  * Агрегировать срез: топ-3 вендорных позиции, топ-3 маржинальных рецепта под ящики снабжения, топ-3 сырьевых товара в глубокой просадке.
* [ ] **Задача 5.2: Интеграция инференса Ollama**
  * Подключить легковесную модель (`llama3.2:3b` или `qwen2.5:7b`).
  * Зафиксировать системный промпт: отвечать строго в виде нумерованного чек-листа оперативных действий.
* [ ] **Задача 5.3: Интеграция рекомендаций в дашборд**
  * Сохранять текстовый вердикт LLM в верхний блок дашборда для чтения перед началом игровой сессии.
* **Артефакт этапа:** Модуль `ai_advisor.py`, выдающий лаконичный инструктаж выкупа, крафта и консервации активов.

## 3. Матрица управления рисками

| Риск | Вероятность | Влияние | Стратегия нивелирования |
| :--- | :---: | :---: | :--- |
| Повреждение файла `Auctionator.lua` при экстренном закрытии клиента | Средняя | Высокое | Чтение из резервного файла `Auctionator.lua.bak` при ошибке десериализации |
| Нехватка RAM / блокировка при разборе больших дампов | Низкая | Среднее | Использование библиотеки `luadata` (C-ускоренной десериализации) вместо медленных регулярных выражений |
| Галлюцинации языковой модели | Средняя | Низкое | Модель получает строго рассчитанные числовые границы и структурированный JSON без права выдумывать цены |
| Разрастание SQLite базы снапшотов | Высокая | Низкое | Введение дедупликационного окна в 10 минут и периодическая архивация снапшотов старше 30 дней |
