# Forever Trade — дизайн-система и спецификация редизайна по референсу DeFiLlama

Дата: 2026-11-03  
Референс: `design_references/02-defillama.png`  
Статус: направление выбрано пользователем; реализация ещё не начата.

## 1. Objective

Перенести визуальный язык DeFiLlama в Forever Trade: тёмный аналитический терминал с левой навигацией, глобальным поиском, компактными метриками, плотными таблицами и спокойным синим акцентом.

Пользователь должен быстрее сканировать торговые сигналы, понимать текущий раздел и состояние данных, а затем открывать инспектор предмета без потери контекста. Редизайн меняет представление, но не торговые решения.

### Принципы

1. **Данные важнее декора.** Никаких маркетинговых блоков, иллюстраций, градиентных hero-секций и лишних CTA.
2. **Один рабочий экран на десктопе.** Прокручиваются таблица и инспектор, а не вся страница.
3. **Акцент обозначает действие или выбор.** Синий не заменяет доменные цвета золота, качества предметов, прибыли и риска.
4. **Плотность без тесноты.** Базовый шаг 4 px, читаемые строки, стабильные числовые колонки.
5. **Автономность прежде всего.** Один `portal.html`, открытие через `file://`, без сборщика, фреймворка, web-font и новой зависимости.

## 2. Подходы

| Подход | Результат | Оценка |
|---|---|---|
| Только заменить CSS | Новые цвета и отступы при старом каркасе | Быстро, но не даёт характерной левой навигации и shell DeFiLlama |
| **Структурный редизайн текущего HTML/CSS/JS** | Новый shell внутри `build_standalone_dashboard()`, существующие данные и обработчики сохраняются | **Выбран** |
| Перейти на React/Tailwind или другой frontend-стек | Полностью новый frontend | Отклонён: ломает автономность и не нужен для статического отчёта |

## 3. Целевой каркас

### Десктоп от 1280 px

```text
┌──────────── sidebar 224 px ────────────┬──────────────── topbar 56 px ────────────────┐
│ Forever Trade                          │ Поиск / Ctrl+K   Realm + freshness   RU/EN │
│ разделы рынка                          ├───────────────────────────────────────────────┤
│ ● Strong Buy                           │ 4 компактные summary-карточки                  │
│ ○ Арбитраж                             ├──────────────────────────────┬────────────────┤
│ ○ Дизэнчант                            │                              │                │
│ ○ Крафт Dual                           │ Таблица активного раздела    │ Инспектор      │
│ ○ Ящики                                │ внутренняя прокрутка         │ внутренняя     │
│ ○ Вендор-шаффл                         │                              │ прокрутка      │
│ ○ Обзор рынка                          │                              │                │
│                                        │                              │                │
│ состояние данных / AI-баннер           │                              │                │
└────────────────────────────────────────┴──────────────────────────────┴────────────────┘
```

- Общий shell остаётся `100vh` и `overflow: hidden` на десктопе.
- Левая колонка содержит существующие семь разделов; это те же `.tab-btn`, `data-tab`, `switchTab()` и `.tab-pane`, а не новая маршрутизация.
- Topbar содержит глобальный поиск, реалм/время данных, Shopping List и переключатель RU/EN.
- Summary остаётся над рабочей областью: четыре карточки в одной строке.
- Таблица и инспектор сохраняют пропорцию примерно 65/35 через `minmax(0, 1.65fr) minmax(320px, 0.85fr)`.
- AI-совет размещается компактно внизу sidebar или под summary, не вытесняя таблицу. Сворачивание использует существующий `toggleAiBanner()`.

### Адаптивность

- **1024–1279 px:** sidebar 72 px с inline SVG и доступными названиями; рабочая область становится одной колонкой, инспектор располагается под таблицей; страница может прокручиваться.
- **768–1023 px:** навигация становится горизонтальной полосой под topbar; summary — сетка 2×2; таблица и инспектор идут последовательно.
- **375–767 px:** topbar переносится на две строки, summary — 2×2, широкие таблицы прокручиваются горизонтально внутри панели. Функции и данные не скрываются.
- Высота мобильного интерфейса не фиксируется через `100vh`; используется обычный поток документа.

## 4. Дизайн-токены

Все значения размещаются в `:root` текущего генератора. Существующие компоненты переводятся на токены без второго параллельного набора цветов.

### Цвета

```css
:root {
  --ft-bg: #0b0e14;
  --ft-sidebar: #0e131b;
  --ft-surface: #11161f;
  --ft-surface-raised: #161d28;
  --ft-surface-hover: #1b2431;
  --ft-border: #263142;
  --ft-border-strong: #35445a;
  --ft-text: #e6edf3;
  --ft-text-secondary: #b7c2cf;
  --ft-text-muted: #8b98a9;
  --ft-accent: #6b9dff;
  --ft-accent-strong: #3b82f6;
  --ft-accent-soft: rgba(59, 130, 246, 0.14);
  --ft-focus: #93b4ff;
  --ft-success: #3fb950;
  --ft-warning: #d29922;
  --ft-danger: #f85149;
  --ft-money-gold: #e3b341;
  --ft-money-silver: #c9d1d9;
  --ft-money-copper: #d8875f;
}
```

Правила:

- `--ft-bg` — фон приложения; `--ft-surface` — карточки и панели; `--ft-surface-raised` — sticky-заголовки, controls и вложенные блоки.
- Основной текст на тёмных поверхностях — `--ft-text`; вторичные подписи — не темнее `--ft-text-muted`.
- Синий применяется к активному разделу, выбранной строке, focus, ссылкам и основному графику.
- Зелёный означает положительный результат, красный — убыток/риск, янтарный — предупреждение или устаревшие данные. Цвет всегда дублируется текстом, знаком или формой.
- Существующие WoW quality colors сохраняются как отдельная доменная шкала `q-*`; они не переопределяются accent.

### Типографика

```css
--ft-font-ui: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
              Helvetica, Arial, sans-serif;
--ft-font-mono: "Cascadia Mono", "SFMono-Regular", Consolas, monospace;
--ft-text-xs: 11px;
--ft-text-sm: 12px;
--ft-text-md: 13px;
--ft-text-lg: 16px;
--ft-text-xl: 20px;
--ft-leading-tight: 1.25;
--ft-leading-ui: 1.4;
```

- UI и таблицы: 12–13 px; заголовок раздела: 16 px/600; название продукта: 16 px/650; KPI: 20 px/600.
- Цены, ROI, Z-score, ID и время используют `font-variant-numeric: tabular-nums`.
- Моноширинный шрифт применяется только к техническим значениям, а не ко всему интерфейсу.
- Длинные названия предметов переносятся максимум на две строки; нельзя обрезать числовые значения.

- Тени только для toast/modal/popover; обычные панели отделяются границами.
- Нет glow, glassmorphism, декоративных градиентов и постоянных анимаций.
- Hover/selection transitions не длиннее 150 ms; `prefers-reduced-motion: reduce` отключает transitions и smooth scrolling.

## 5. Компоненты и состояния

### Sidebar и навигация

- Логотип заменяется текстовым wordmark Forever Trade и короткой подписью WoW Forever.
- Кнопка раздела: высота 36 px, radius 6 px, иконка 16 px, текст 13 px.
- Активная кнопка: `--ft-accent-soft`, синяя левая полоса 2 px, основной текст.
- Hover: `--ft-surface-hover`; focus-visible: внешнее кольцо 2 px `--ft-focus`.
- Иконки — локальные inline SVG с `currentColor`, без emoji и внешней icon-библиотеки. Декоративные SVG получают `aria-hidden="true"`.

### Topbar и controls

- Поиск занимает доступную ширину, минимум 220 px на широком экране; placeholder и подсказка Ctrl+K остаются.
- Кнопки и select имеют высоту 32 px, видимую границу, hover, active, focus-visible и disabled.
- Shopping List — основная text-button, но не крупный маркетинговый CTA.
- Переключатель языка — segmented control; активный язык обозначается и фоном, и `aria-pressed`.
- Realm, freshness и время обновления остаются видимыми; устаревание данных нельзя обозначать только цветом.

### Summary cards

- Четыре равные карточки с подписью, значением и коротким контекстом.
- Padding 12–16 px, граница 1 px, radius 6 px.
- Значение не меняет ширину карточки при обновлении; числа табличные.
- Карточки не превращаются в крупные dashboard-hero.

### Таблицы

- Контейнер имеет собственную прокрутку; header остаётся sticky.
- Строка 40 px, горизонтальный padding ячейки 12 px, вертикальный 8 px.
- Заголовки 11 px/600, без агрессивного uppercase; сортируемые заголовки сохраняют `data-sort` и получают понятный индикатор направления.
- Hover: тонкая смена фона; selected-row: `--ft-accent-soft` плюс левая полоса.
- Числовые колонки выравниваются вправо; название предмета — влево.
- Empty state занимает панель и содержит конкретное объяснение; нулевые данные не подменяются прибыльным сигналом.

### Инспектор

- Сохраняются заголовок, Wowhead-ссылка, copy, график, калькулятор сделки, Disenchant и crafting DAG.
- Секции отделяются границами и заголовками, а не набором тяжёлых вложенных карточек.
- Метрики калькулятора — definition grid: подпись слева/сверху, значение справа/снизу, прибыль и ROI имеют текстовый знак.
- Выбранный предмет остаётся видимым при переключении RU/EN и разделов.
- На узких экранах инспектор идёт после таблицы, без modal-only сценария.

### Графики

- Python `_build_price_history_chart()` и JS `updateInspectorChart()` используют одну палитру.
- Фон совпадает с панелью; сетка — `--ft-border` с пониженной непрозрачностью; подписи — `--ft-text-muted`.
- Цена: `--ft-accent`; средняя цена: `--ft-warning`; безубыток: `--ft-danger`.
- Линии средней цены и безубытка различаются также `dash`/`dot`.
- Tooltip и legend не перекрывают основной ряд данных; график остаётся responsive и без modebar.

### Toast и modal совместимости

- Toast имеет поверхность `--ft-surface-raised`, границу и тень; длительность и тексты не меняются.
- Существующий `#item-modal` остаётся DOM-совместимым, даже если основной сценарий использует инспектор.
- Скрытые compatibility-элементы не становятся видимыми после редизайна.

## 6. Неизменяемые функциональные контракты

Редизайн не должен менять:

- алгоритмы Strong Buy, Vendor Arbitrage, Disenchant, Dual Crafting, Waylaid Crates, Vendor Shuffle и Market Overview;
- цены, комиссии, депозиты, ROI, Z-score, freshness и фильтрацию сигналов;
- `ITEM_STORE`, `STRONG_BUY_ITEM_IDS` и сериализацию данных;
- `ft_active_tab`, `ft_search`, `ft_lang`, `ft_selected_item` в `localStorage`;
- RU/EN через `setLanguage()`, поиск через `onItemSearch()`, Ctrl/Cmd+K;
- сортировку `.sortable`, `switchTab()`, выбор строки и `selectInspectorItem()`;
- Plotly-график и калькулятор;
- Wowhead Forever links/tooltips;
- копирование имени и Auctionator Shopping List;
- автообновление 30 секунд и открытие итогового файла без локального сервера.

Существующие ID, классы и JS-функции сохраняются, если они нужны текущей логике или тестами. Перенос элемента в другой контейнер допустим; переименование ради стиля — нет.

## 7. Tech Stack и Project Structure

- Python 3, стандартная генерация HTML в `src/dashboard.py`.
- Standalone HTML/CSS/JavaScript, SQLite как источник данных, Plotly и Wowhead tooltips по существующей схеме.
- `src/dashboard.py` — разметка, токены, стили, JS и генерация `portal.html`.
- `tests/test_dashboard.py` — структурные и функциональные контракты генератора.
- `portal.html` — генерируемый артефакт, не редактируется вручную.
- `design_references/02-defillama.png` — визуальный референс, не источник готового кода.
- `docs/superpowers/specs/` — эта спецификация; `docs/superpowers/plans/` — план внедрения.

## 8. Code Style

Сохраняются текущие Python f-string/placeholder-шаблоны, двойные фигурные скобки в CSS/JS и существующие имена обработчиков. Стили группируются по компонентам и используют токены:

```css
.tab-btn {
    min-height: 36px;
    padding: var(--ft-space-2) var(--ft-space-3);
    color: var(--ft-text-secondary);
    border: 1px solid transparent;
    border-radius: var(--ft-radius-md);
    transition: background-color var(--ft-transition), color var(--ft-transition);
}

.tab-btn:hover {
    color: var(--ft-text);
    background: var(--ft-surface-hover);
}

.tab-btn:focus-visible {
    outline: 2px solid var(--ft-focus);
    outline-offset: 2px;
}
```

Новые комментарии не добавляются без необходимости. HTML-шаблон и данные не дублируются ради отдельных тем.

## 10. Testing Strategy

1. **Сначала контрактные тесты:** добавить/обновить структурные проверки sidebar/topbar и нового shell в `tests/test_dashboard.py`.
2. **Сохранить поведение:** существующие проверки ID, данных, локализации, JS-обработчиков и генерации не удаляются.
3. **Осознанно обновить layout-тест:** проверка старого 65/35 и `100vh` заменяется на проверку нового grid, сохраняющего десктопный одноэкранный режим и адаптивные breakpoints.
4. **Полный прогон:** `python -m pytest`; ожидается отсутствие новых ошибок, фактическое число тестов фиксируется по результату.
5. **Реальный артефакт:** сгенерировать `portal.html` штатной командой и открыть именно его через `file://`.
6. **Браузерная приёмка:** 1440×900, 1024×768, 768×1024 и 375×812; консоль без новых ошибок; отсутствуют непредусмотренные overflow и перекрытия.
7. **Сценарии:** все семь разделов, поиск, Ctrl+K, сортировка, выбор строки, график, калькулятор, DAG, Disenchant, RU/EN, copy, Shopping List, сохранение состояния после reload и автообновление.
8. **Доступность:** клавиатурный фокус, текстовые альтернативы состояниям, reduced motion, читаемый контраст и горизонтальная прокрутка таблиц на мобильном.

## 11. Boundaries

- **Всегда:** сохранять автономный файл, данные и торговые формулы; запускать тесты; проверять сгенерированный HTML в браузере.
- **Сначала спросить:** любые новые зависимости, изменение схемы БД/ETL, смена frontend-стека, удаление функциональных тестов или пересмотр торговых порогов.
- **Никогда:** не менять аналитику ради визуального результата, не редактировать только `portal.html` в обход генератора, не добавлять внешние шрифты/иконки, не коммитить без прямого запроса пользователя.

## 12. Success Criteria

- Визуально портал считывается как близкий по типу к выбранному DeFiLlama: sidebar, тёмные панели, синий accent, плотные таблицы, спокойные карточки.
- На 1440×900 активный раздел, таблица и инспектор помещаются в один экран; длинные данные прокручиваются внутри панелей.
- Все семь разделов и существующие интерактивные сценарии работают на сгенерированном `portal.html`.
- RU/EN и четыре ключа состояния переживают reload; автообновление не сбрасывает выбранный раздел, поиск и предмет.
- На 375 px нет горизонтального overflow всей страницы; широкая таблица прокручивается локально.
- Нет новых зависимостей и изменений торговой логики.
- Полный набор pytest зелёный, браузерная консоль не содержит новых ошибок.

## 13. Assumptions и Open Questions

- Основной режим — десктопный одноэкранный терминал; мобильная версия адаптирует поток, но не удаляет функции.
- Текущие summary-метрики и семь разделов остаются без переименования бизнес-логики; допускается только визуальная компоновка существующих RU/EN текстов.
- AI-баннер сохраняется, но становится вторичным элементом.
- Открытых вопросов нет: пользователь уже выбрал референс №2 и запросил дизайн-систему вместе с планом.
