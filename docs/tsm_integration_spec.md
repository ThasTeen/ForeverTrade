# Спецификация автономного торгового ядра и микро-аддона ForeverTrade_Sniper

Документ определяет архитектуру перехода Forever Trade на **100% автономный стек без внешнего TSM**:
- Отказ от установки и зависимости от внутриигрового аддона TSM.
- Собственный микро-аддон `ForeverTrade_Sniper` (250–300 строк Lua), использующий портированные низкоуровневые алгоритмы сканирования TSM.
- Автоматическая генерация конфигурации цен и таргетов из Python-демона прямо в папку аддонов WoW.
- Портирование математических ядер и таблиц данных TSM (Hampel Filter, EWMA, Disenchanting, DAG-крафт) в `src/analytics.py`.

---

## 1. Концепция: Разделение мозга и исполнителя

В условиях мега-сервера Forever с сотнями тысяч игроков время жизни ошибочного лота составляет **2–8 секунд**. Оффлайн-модель через `/reload` не успевает, а тяжелый TSM перегружает клиент.

Решение:
1. **Аналитический мозг (Python-демон Forever Trade):**
   - Анализирует историю аукциона (`Auctionator.lua`).
   - Рассчитывает справедливые рыночные цены через робастный Hampel Filter и EWMA.
   - Фильтрует неликвид по коэффициенту $L \ge 0.50$.
   - Генерирует плоскую хеш-таблицу таргетов с максимальными ценами выкупа.
   - Автоматически сбрасывает `config.lua` в папку `Interface/AddOns/ForeverTrade_Sniper/`.
2. **Микро-исполнитель (`ForeverTrade_Sniper.lua`):**
   - Ультралегкий Lua-аддон (< 50 КБ памяти, 0 сторонних библиотек, без Ace3).
   - Непрерывный опрос последней страницы `lastPage` через `QueryAuctionItems` каждые 1.2–1.4 секунды.
   - Моментальная сверка `buyout <= FT_TARGETS[itemId]` за $O(1)$.
   - Звуковой алерт и привязка макроса выкупа к колесу мыши (1 скролл = 1 аппаратное действие выкупа).

## 2. Архитектура микро-аддона `ForeverTrade_Sniper`


### 2.2. Портированные механизмы из TSM Sniper

Из исходников TSM (`AuctionScan/Core/Sniper.lua` и `AuctionUI/Sniper.lua`) напрямую заимствуются 4 боевых механизма:

#### 1. Индексация последней страницы и компенсация сдвига (Page Shift):
Сервер сортирует базу аукциона хронологически. Новые лоты всегда помещаются в конец.
```lua
local totalCount = select(2, GetNumAuctionItems("list"))
local lastPage = math.max(0, math.ceil(totalCount / 50) - 1)

-- Если количество лотов на границе переключения страницы (1-5 лотов),
-- дополнительно проверяем предыдущую страницу, чтобы не потерять лоты при сдвиге:
if (totalCount % 50) > 0 and (totalCount % 50) <= 5 and lastPage > 0 then
    -- Проверка lastPage - 1
end
```

#### 2. Соблюдение Token-Bucket рейт-лимита сервера:
Сервер WoW Classic Era блокирует запросы чаще ~1.2 секунды. Аддон слушает функцию готовности:
```lua
local frame = CreateFrame("Frame")
local timeSinceLastQuery = 0

frame:SetScript("OnUpdate", function(self, elapsed)
    timeSinceLastQuery = timeSinceLastQuery + elapsed
    if timeSinceLastQuery >= 1.2 and CanSendAuctionQuery() then
        timeSinceLastQuery = 0
        QueryAuctionItems("", nil, nil, lastPage, 0, 0, false, false, nil)
    end
end)
```

#### 3. Фильтрация дубликатов (LRU Ring-Buffer):
Чтобы звуковой алерт не звонил повторно на один и тот же лот, ведётся кэш из последних 200 просмотренных лотов по ключу:
`hash = itemId .. "_" .. owner .. "_" .. buyout .. "_" .. timeLeft`.

#### 4. Безопасный выкуп через колесо мыши (Hardware Event):
Вызов `PlaceAuctionBid` защищён движком игры от вызова из скриптов. Решение TSM — создание невидимой защищённой кнопки `SecureActionButtonTemplate` с перехватом клика:
```lua
local buyBtn = CreateFrame("Button", "FTSniperBuyBtn", UIParent, "SecureActionButtonTemplate")
buyBtn:SetAttribute("type", "macro")

function FT_ArmSniperBuy(index, buyout)
    PlaySoundFile("Sound\\Interface\\AuctionWindowOpen.ogg")
    buyBtn:SetAttribute("macrotext", string.format("/click AuctionList%dItem\n/run PlaceAuctionBid('list', %d, %d)", index, index, buyout))
    SetOverrideBindingClick(buyBtn, true, "MOUSEWHEELUP", "FTSniperBuyBtn")
    SetOverrideBindingClick(buyBtn, true, "MOUSEWHEELDOWN", "FTSniperBuyBtn")
end
```
Игрок слышит гонг $\to$ делает один скролл колеса мыши вверх/вниз $\to$ лот выкуплен за доли секунды.

## 3. Мост «Python-демон ↔ Микро-аддон»

### 3.1. Генерация `config.lua`
В `src/analytics.py` реализуется функция `export_sniper_addon_config()`:
- Анализирует текущую базу цен.
- Отбирает только ликвидные позиции ($L \ge 0.50$): ткань, руду, травы, эликсиры, сумки, реагенты ящиков Waylaid Crates.
- Вычисляет потолок выкупа:
  $$\text{MaxBuyout}(i) = \min(0.65 \times \text{dbmarket}(i), \quad P_{\text{vendor\_sell}}(i) - 50c)$$
- Записывает `config.lua` по пути `$WOW_PATH/Interface/AddOns/ForeverTrade_Sniper/config.lua`:
  ```lua
  -- Generated by Forever Trade Engine. DO NOT EDIT MANUALLY.
  FT_SNIPER_CONFIG = {
      version = 1,
      min_profit_copper = 1000,
      targets = {
          [2589] = 120,    -- Linen Cloth: выкуп <= 1s 20c
          [2770] = 350,    -- Copper Ore: выкуп <= 3s 50c
          [118]  = 4500,   -- Minor Healing Potion
          [211501] = 8500, -- Waylaid Supplies target
      }
  }
  ```

## 4. Портирование алгоритмов и данных TSM в Python-бэкенд

Всё математическое превосходство TSM переносится прямо в `src/analytics.py` и `data/`:

### 4.1. Робастный DBMarket и Hampel Filter (отсечение выбросов)
- **Замена классической $\sigma$ на робастную $\sigma_{\text{MAD}}$:**
  $$\text{MAD} = \text{median}(|P_i - \tilde{P}|), \quad \sigma_{\text{MAD}} = 1.4826 \times \text{MAD}$$
- Точки с $|P_i - \tilde{P}| > 3 \times \max(\sigma_{\text{MAD}}, 0.10 \tilde{P})$ исключаются из ядра (тролль-лоты за 999g больше не ломают среднее).
- Экспоненциальное затухание (EWMA) с полураспадом 3.5 дня: $w_i = \exp(-\lambda \Delta t)$.

### 4.2. Liquidity Score ($L$) — защита от неликвидных ловушек
- Расчет коэффициента $L \in [0.01, 1.0]$:
  $$L = \alpha L_{\text{obs}} + (1 - \alpha) L_{\text{intrinsic}}$$
- Расходники/сырье/ящики получают $L \ge 0.90$. Мусорная синька и редкие выкройки получают $L \le 0.25$.
- Предметы с $L < 0.20$ помечаются как `ILLIQUID_TRAP` и исключаются из снайпинга.
- Учет стоимости заморозки капитала при оценке чистой прибыли:
  $$\Pi_{\text{adj}} = \mu \times 0.95 - P_{\text{curr}} - \frac{\text{deposit}}{L} - (1 - L) \cdot 0.10 P_{\text{curr}}$$

### 4.3. Disenchant Shuffle (арбитраж распыления)
- Из `TradeSkillMaster/Data/Disenchanting.lua` извлекаются матрицы матожидания $\mathbb{E}[\text{mats}]$ для Era 1.15 и сохраняются в `data/disenchant_tables_era.json`.
- Метод `get_disenchant_arbitrage()` находит на аукционе экипировку, выставленную дешевле стоимости выпадающих пыли, эссенций и осколков минус 5% комиссии:
  $$\text{Profit} = \mathbb{E}[\text{DE Value}] \times 0.95 - P_{\text{buyout}} \ge \text{min\_profit}$$
- Новый таб в Goblin Terminal: `✨ Дизэнчант`.

### 4.4. Рекурсивный DAG-крафт (Make-vs-Buy)
- Расчет себестоимости полуфабрикатов по минимальной ветке:
  $$\text{MatPrice}(r) = \min(P_{\text{vendor\_buy}}(r), P_{\text{ah}}(r), C_{\text{craft}}(r))$$
- Если на аукционе нет рулонов ткани или медных трубок, крафт не бракуется, а считается из базовой ткани и руды.
